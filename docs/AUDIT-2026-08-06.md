| `?scene=hex` | `HexScene` | `HexGrid` | frozen reference |
| `?scene=queen` | `QueenScene` | none | model preview |

The **density SDF + Surface Nets** stack won. The entire voxel world model is legacy,
reachable only from `?scene=dig`/`?scene=hex`. Four live utilities are misfiled inside
`src/voxel/` (`carve.ts` — load-bearing for all nest carving, `locomotion.ts`, `room.ts`,
`clodBurst.ts`).

### The live island pipeline (~12 files)

- **Terrain**: baked Kauai 1025² int16 grid → 64 sections built once, never touched.
  BE's seven-band biome shader (`islandBiome.ts`). Walker grounds on the *drawn* triangles.
- **Fine soil**: `IslandStream` — 192×256×192 mm window at 1 mm cells (~38 MB fixed),
  floating depth band with hysteresis, sparse edit store keyed by absolute position,
  chunk = slide tile, mesh budget 3–12/frame with a ~6 ms wall-clock break, clip
  rectangle that provably never outruns built chunks.
- **Nest**: `nestPlan` (graph, single source of truth) → `nestCarve` (SDF) → folded into
  the soil function by `islandSoil.setPlan()` → `NestDesigner` UI → plan edges double as
  the **rail network**.
- **Digging**: `BoreControl` (pure, tested state machine; hold-to-dig, stroke at 0.42 s,
  bite lands at stroke bottom) → `IslandScene.bite()` cuts one 1.75×0.5 mm mouthful with
  a set-back sphere at the **real jaw bone** (`jawPosition`), pushed to hull front.
- **Movement gate**: `bodyFits()` — 11-point shell of her measured ellipsoid. She only
  moves into space already chewed.
- **Animation**: `hexapod.gaitPose` (clock-driven procedural gait) → `QueenModel.solveFeet`
  (CCD IK, accepts an arbitrary `up + surface(x,y,z)` frame).
- **Presentation**: `undergroundSense` (sensed contour bands, a bubble not an x-ray),
  trail-following underground chase camera, adaptive pixel ratio for phones.

### THE key structural fact: four parallel locomotion systems

| System | Scene | Ground primitive | Walls/ceilings | Feet |
|---|---|---|---|---|
| Rail (GRIP) + heightfield free-walker + `moveBore` | **Island** | `floorBelow` (1-D column scan) | shafts only, via rail's "remembered wall" | clock gait + `solveFeet`; **no world-anchored stepper → feet skate** |
| `TripodGait` + climb adhesion | **DTL** | `groundAt(fromY)` + 5-sample stance median + `descendInto` ring + roof-cone sense | walls via climb (`castBarrier`), not inside tunnels | world-anchored stepper (zero foot slide) + `solveFeet` with climb frame |
| `LegDrive` + `hold()`/`fall()` | **BlockScene** | cast along −up; `nearestSurface` 6-direction march; `senseRoom` 14-ray spray | **full six-face incl. underside** | feet lock to world and **constrain the body** (`v + ω×r`, twist clipping) |
| `SurfaceFrame` six-axis | DigScene | voxel supports | yes (legacy) | first-person capsule, no model |

Fixes made in one system have repeatedly not propagated to the others — this is the
single largest source of recurring bugs (see §5).

### Everything else

- **Colony systems don't exist yet.** `PheromoneField`/`FoodNode`/`GameState`/`antCastes`
  are orphaned 2D Phaser-era stubs imported only by `tests/core.test.ts`.
  `antCastes` even uses a different caste taxonomy (minor/worker/major/superMajor) than
  the rigs (queen/worker/major). No AI, no brood, no multi-ant simulation.
- **Tests**: 511 unit tests, all green; typecheck clean (strict + `noUncheckedIndexedAccess`).

- **Deploy**: GitHub Actions → Pages, with a `/preview/` dual-publish. Recent

## 3. CURRENT PROBLEM AREAS

### a) Locomotion is fragmented and the island got the weakest version
The island — the shipping scene — has no world-anchored foot stepper (feet skate), no
real wall support (a `CLIMB_RATE` hack eases her up when blocked with headroom), a
hard-coded rail for planned tunnels only, and a bespoke `moveBore` for hand-dug bores.
DTL and BlockScene each independently solved parts of this better.

### b) Underground movement on the island is a tower of special cases
`railEdge`, `railT`, `railDir`, `railRev`, `railWall`, `boreEngaged`, `chamberId`,
`chamberGrabArmed`, `gateAsk`, `enterDeclined`, `surfaceDeclined`, `ventLidAt`,
`chamberMouthGrab`, vertical-bore reverse latches… Each flag is a patch over a case the
underlying "find the floor below" model can't express. The commit history shows these
flags being added, removed, and re-added as each patch exposed the next case.

### c) The ground primitive is 1-D
Nearly every contact question is "elevation of the surface along one up axis"
(`floorBelow`, `footingFrom`, `groundAt`, `footTarget`). A tunnel wall, a ceiling, and
a shaft have no elevation along a single up — hence the recurring
foot-jumps-to-the-summit, hauled-out-of-her-own-shaft, and stuck-at-the-rim bugs.
`solveFeet`'s frame parameter mitigates but the frame itself is guessed from the aim
(`boreFrame`), not measured from contacts.

### d) Gravity is rule-based, not support-based
Island: "underground = no falling" (literally: bored-in movement has no gravity at all,
rail crawling has none). DTL: `wedged` (body below undug land) suspends gravity — better,
still a proxy. BlockScene has the model you asked for: **gripping** (contact found) vs
**falling** (no contact) — but only BlockScene has it.

### e) Digging is now honest but unplayably slow — a known, open problem
`7752368` states it: ~75 bites per mm of passage, ~half an hour of held DIG for a 20 mm
entrance shaft. The physical model (jaw anchor, stroke cadence, no teleport, oval gate)
is right; only the per-stroke *yield* is wrong. See §7 Phase 2.

### f) Body fit: right idea, three flaws
- Measured via `Box3` over the whole model **including antennae and mid-stride legs**,
  so the oval is fatter than her body; the jaw bone then falls *inside* the hull and the
  bite has to be artificially pushed out (`IslandScene.bite()` hull correction).
- The shell test is **yaw-only** — the oval never pitches with the aim, so a steep bore
  tests the wrong volume.
- Caste-awareness exists in DTL (measures the driven caste) but the island is queen-only.
- The grey/green/red display you want already exists (grey = not governing, i.e. FREE).

### g) IslandScene is a god-class
2,944 lines owning terrain, streaming, meshing, rail state machine, bore, body fit,
gates, designer lifecycle, cameras, HUD, and input. All physics are private methods —
untestable except through Playwright.

### h) Tests prove the wrong layer
Helper modules: superb. Scenes (where grip, gravity, body-fit, reverse-out, camera
collision actually live): zero unit tests. The behaviours that keep regressing hang on
single assertions inside one 96 KB probe that CI never runs. ~20 tests exercise dead
code. ~40 probes are abandoned one-off debug scripts.

### i) Concrete bugs found (verified in current code)
1. **Island digs are lost on refresh** — `IslandStream` has no
   `serializeEdits`/`restoreEdits` (TerrainStream has both; DTL persists to localStorage).
2. **Only the first entrance mound is drawn** — unconditional `break` in
   `islandSoil.moundTopMm` (and its twin in `worldScape.ts`): a second anthill is carved
   into the soil but never stamped into the drawn island surface.
3. **Rails ignore edge bows** — `rebuildRails` uses straight chords; a bowed tunnel is
   carved as a curve and ridden as its chord (latent: the designer can't author bows yet,
   but `demoNest` proves plans can carry them).
4. **Nest SDF cost** — `densityUnder` evaluates ~120 closures per sample per 60 mm of
   tunnel inside the reject box; `applyPlan`/regenerate over a real nest is the biggest
   hitch in the codebase. `NestDesigner` also rebuilds *all* nest geometry on every
   pointermove during a drag.

### j) Camera
Underground trail-chase + chamber camera is genuinely good (the trail is guaranteed
inside the tunnel). Weaknesses: the walk-back-along-trail escape when the camera lands
in soil is a loop of `lerp(at, 0.3)` (can still end a frame inside a wall);
`FollowCamera` (742 LOC) has zero tests.

### k) Deployment (kept separate from game code, per your instruction)
- `deploy-pages.yml` has `concurrency: cancel-in-progress: true`. GitHub's own Pages
  starter ships `false` with a comment describing exactly your symptom (a cancelled
  in-flight deployment wedges the queue). **Most likely repo-side cause of
  `deployment_queued`.**
- The artifact is ~45 MB: `/preview/` duplicates all 28 MB of `public/` (and the preview
  branch currently points at the same commit as `main`, so it's a byte-identical copy),
  `sourcemap: true` ships three.js maps twice, and 17.8 MB is four HDR skies used only
  by the legacy dig room.
- Also verify in Settings that Pages **Source = GitHub Actions** (the one hypothesis that
  fully explains "green build, queued forever"; `3343103` names it).

## 5. ROOT CAUSE ANALYSIS — why digging / shafts / foot contact keep breaking

1. **The wrong universal primitive.** Almost every question is asked as "surface
   elevation along one up" — a heightfield question. Tunnels, shafts, walls and ceilings
   are precisely the places where that question has no answer, so each one became a
   special case with its own flag, and each flag interacted with the others
   (`wedged` × `roofed` × `boreEngaged` × `railEdge` × `chamberId` × `underground`).
   The correct primitive — "what surfaces are near this point, in which directions?" —
   already exists (`senseRoom`, `nearestSurface`, `Ground.nearest`) but never became the
   foundation.
2. **Support is inferred, not measured.** Whether she is held up is derived from proxies
   (below undug land? roof overhead? button held? on a rail?) rather than from actual
   contacts. Every proxy has an edge case at the mouth of a shaft, and the history shows
   each one being discovered by playtest (the 7.0–9.8 mm limit cycle, the 46 mm launch,
   the 2.3 s "dead" crater state).
3. **Four implementations, zero sharing.** The skating fix (TripodGait) never reached the
   island; the adhesion model never left the block; the per-foot ground fix (`a9cc5bc`)
   was island-only. Every scene re-fights the same war because physics live as private
   methods of god-scenes.
4. **The regression net has holes exactly where the bugs are.** Scene physics are only
   covered by manual, mostly print-only probes. A fix proven by a probe on Tuesday can be
   silently un-fixed on Thursday because CI never runs it.
5. **Spec oscillation without recorded decisions** (hold-to-dig ↔ latch, aim from camera
   ↔ dial, auto-surface ↔ prompt — each reversed at least once). `BoreControl`'s header
   shows the cure: record the reversal *and* pin it with a test.

## 6. RECOMMENDED TARGET ARCHITECTURE

Keep your proposed flow, with two refinements: **SurfaceContact feeds a SupportState**
(that is what decides gravity), and **BodyFit is consulted by both digging and
locomotion** rather than sitting between them.

```
Input (stick / keys / DIG)
  ↓
Intent  (walk vector, aim dial, dig held)        BoreControl (exists, keep)
  ↓
DigController      — bite at jaw, stroke cadence, yield multiplier
  ↓ (edits field)
TerrainQuery       — ONE interface over stream/field:
                     solidAt / densityAt / castRay / nearestSurface / senseRoom
  ↓
SurfaceContact     — per-foot & body contact search (cone/spray), returns
                     {point, normal, distance, valid} per contact
  ↓
SupportState       — enough grips? → SUPPORTED (adhesion) | UNSUPPORTED (gravity)
  ↓
BodyFit            — "can the oval occupy this pose?" (pitch-aware, caste-sized)
  ↓
Locomotion         — one mover: proposes twist, clips against contacts + fit
                     (BlockScene's hold/fall generalised; rails demoted to a
                     navigation aid, not a physics mode)
  ↓
Body orientation   — aimUp toward blended contact normals (eased + rate-limited)
  ↓
Foot IK            — TripodGait anchors → solveFeet with the contact frame
  ↓
Animation          — gaitPose (clock parts: antennae, mandibles, sway)
  ↓
Camera             — trail-chase underground, FollowCamera above, first person
```

Rules of thumb the history itself teaches:
- Digging **only** edits the field and reports the bite. It never moves or orients her.
- Gravity is decided **only** by SupportState. No "underground" special case.
- Position changes go through **one** mover that always consults BodyFit.
- Every module above the scene line is pure/renderer-free and unit-tested
  (`BoreControl` and `TripodGait` prove the codebase can do this well).
- The rail system survives as *assistance* (snap-to-centerline steering inside planned
  bores, camera hints), not as a second physics.

This does not paint the future into a corner: worker head/mandible targeting is another
consumer of the same contact + orientation machinery (aim head at target, body assists —
the DTL pitch train is the prototype); combat and carrying hang off DigController's
sibling (an InteractionController); multiple ants are more instances of
Locomotion + FootIK, which is why the per-frame cost discipline (§3i, §7) matters now.

**Phase 5 — worker interaction/carrying** (head targeting: yaw/pitch/roll with body

**Phase 6 — combat, quests, colony progression, more ants** (needs the Phase-1 modules

The order you proposed is right; the only change is inserting island adoption (Phase 3)
before the prologue, because the prologue is scripted on top of exactly the systems
Phases 1–2 stabilise.

## 8. RISKS

- **The island's rail/gate/chamber state machine is load-bearing** for the designer flow
  and `probe-island`'s prologue path. Replacing it wholesale is the biggest regression
  risk — hence "steering assist" demotion, incremental, behind the Phase-1 tests.
- **Gravity changes historically produce launches and sinkings** (46 mm launch, 7–9.8 mm
  limit cycle, half-millimetre BORE-press step — all in the log). Contact-based support
  must land with the reverse-out and idle-doesn't-sink tests *first*.
- **`solveFeet`/gait changes affect all four scenes at once** — the queen bench
  (DTL/Block) is the canary; keep it.
- **Dig-yield tuning invalidates probe budgets** (smoke-density's mm-per-second and
  volume assertions) — update them in the same PR.
- **Stream consolidation** (three near-identical classes) is tempting and risky; the edit
  store is the crown jewels. Do it only behind the terrainStream test suite, or not yet.
- **Deleting dead code** (`excavation*`, `core.test.ts`, voxel museum) is safe for the
  game but will shrink the green-test count CI displays; do it as its own reviewable PR.

- U: foot contact search from inside a burrow never returns the surface overhead
